# 环境与主机准备

[返回手册首页](../README.md) · [测试网版本与接入资料](../networks/testnet.md)

适用范围：Linux 上通过发布安装包部署普通 USDB 节点。首次安装状态和版本限制见[版本页](../networks/testnet.md#版本与验证范围)。

## 机器要求

| 项目 | 要求与建议 |
| --- | --- |
| 系统 | Linux，内核至少 5.10；采用 systemd 管理后台启动任务 |
| 架构 | x86-64 / amd64 |
| 发行版 | Ubuntu 24.04 是优先运维基线；自动准备工具支持 Ubuntu 22.04/24.04/26.04 和 Debian 12/13 |
| CPU | 建议至少 8 个逻辑核 |
| 内存 | 建议至少 32 GiB；工具要求系统实际可用的内存额度至少为 32 GB（十进制），受限虚拟机也需满足 |
| 数据盘 | 建议至少 2 TiB NVMe；首次配置要求所在文件系统的**总容量和当前可用空间均不少于 1.5 TiB** |
| Docker | Linux rootful Docker Engine 至少 28.0.0；不支持 rootless 或 Docker Desktop |
| Compose | `docker compose` 插件至少 2.33.1 |
| 网络 | 稳定出站网络；可以解析 DNS、同步时间、访问 HTTPS 下载源和 Bitcoin/USDB peers |

磁盘空间要容纳完整节点数据、启动文件及同步过程中的临时占用。标称 2 TB 的磁盘通常小于 2 TiB；已有备份和其他服务占用也会减少可用空间。首次检查通过后，仍需持续监控余量。

首次同步耗时与网络、磁盘和主机负载有关，应安排持续运行的时间窗口。不要把某个阶段的 ETA 当成整个部署的完成时间。

## 运行账号与数据盘

选择一个普通运维账号，并始终使用它执行安装器和 `usdb-node`。可以使用已有账号；不要求用户名必须为 `usdb`。账号需要可用的 sudo 权限，用于准备软件和安装后台管理服务。

Docker 组拥有主机级控制权限，只给需要管理节点的账号授权。不要为了绕过权限错误改用 `sudo usdb-node setup`，否则可能把配置写入另一个账号的主目录。

在安装前确认大容量数据盘已挂载。假设准备使用 `/data/usdb`，可以先检查它的上级挂载点：

```bash
id -un
uname -m
free -h
findmnt --target /data
df -h /data
```

若没有 `/data`，请改用实际数据盘路径。确认挂载设备和容量正确，再为当前运维账号准备一个可写的数据目录。不要把尚未挂载的数据盘路径误认为已可用；也不要递归修改已有其他服务目录的所有者。

`setup` 会再次检查所选目录所在文件系统。只有主目录所在磁盘足够大时，才使用默认的 `~/.usdb`。

## 安装器所需的最少软件

安装器需要 Bash、curl、Python 3、tar 和 sha256sum。在 Ubuntu/Debian 空白主机上，可先执行：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl python3 tar coreutils bash
```

其他发行版使用对应的包管理器安装上述工具。Docker、Compose、Git 和 jq 等完整节点依赖，在安装节点工具后通过 `usdb-node prepare-host` 检查和准备，步骤见[安装与入网](install.md)。已有容器工作负载的主机如提示软件包冲突，先处理冲突，不直接卸载现有运行时。

## 端口与防火墙

| 端口 | 部署要求 |
| --- | --- |
| 实际 SSH 端口 | 保持运维可达，可限制可信来源 |
| `31303/TCP`、`31303/UDP` | 为 USDB 节点通信和发现开放；同时核对云安全组、主机规则和路由器转发 |
| `8333/TCP` | Bitcoin 入站连接，可选；普通节点保持默认不公开即可 |
| `8332`、`8545`、`8546`、`28010`、`28020`、`28040` | 私有服务接口，不开放到公网 |

公网浏览器和公共 RPC 应通过专用服务提供，不能直接公开节点的 `8545/8546`。同机或独立部署的入口与查询节点要求见 [USDB Explorer](../services/explorer.md)。

配置向导提供两种防火墙方式：

- **external，默认**：你使用云安全组、虚拟化平台或自己的主机防火墙管理规则。节点工具不会安装或检查 UFW，需自行确认上表要求。
- **managed**：节点工具使用 UFW 管理主机规则，操作会使用 sudo，并要求确认实际 SSH 服务端口。上游云安全组或路由器仍需自行配置。

Docker 的端口发布可能绕过普通 UFW 规则，不能只凭一条 deny 规则判断 RPC 已被保护。保留安装工具设置的本地接口绑定，并从主机之外复核暴露面。

IPv6 节点还需要主机具备可用的 IPv6 地址和默认路由，并在对应地址族放行 P2P。只有 IPv6 Seed、没有实际 IPv6 出站能力的节点无法连接它。

## 双栈准备检查

包含双栈准备提示改进的版本，会在 `prepare-host`、`host check` 和 `host install` 的基础依赖检查通过后显示 `P2P host check`，预览当前主机在 `auto` 模式下将选择的地址族。它只检查，不修改网卡、路由、sysctl 或已有节点配置。

- `family=dual`：当前本机检查通过；仍需确认容器网络、防火墙与真实 peer 连接。
- `WARNING P2P_IPV4_FALLBACK`：当前自动配置会选择 IPv4。根据提示检查稳定 IPv6 地址、默认路由、RA 接收策略以及 Docker 运行时。
- 基础软件检查通过不代表 IPv6 就绪。只使用 IPv4 的节点可以继续；需要连接 IPv6 Seed 时，应先修复问题，再在向导中明确选择 `dual` 或 `ipv6`。

**r28 及此前版本没有这组主机准备提示。** 这些版本需要自行执行地址和路由检查，并在首次 `setup` 时传入 `--p2p-ip-family dual`；已配置节点使用 `peers configure`。具体命令、`accept_ra=2` 的持久配置及恢复标志见[IPv6 诊断与恢复](peers.md#ipv6-诊断与恢复)。

完成以上准备后，继续[安装与入网](install.md)。

# 进阶：规划和创建自己的网络

[返回手册首页](../README.md) · [配置文件与参数](configuration.md)

本章面向希望运行独立 USDB 网络的社区、实验网络和网络运营者。你可以先不阅读代码，了解需要决定哪些参数、哪些材料必须一致，再与构建维护者一起生成可交付的网络包。只是加入已有网络、运行更多 follower 或改变本机端口时，仍按[安装与入网](../node/install.md)操作，无需创建网络。

**当前能力边界（2026-10-03）：源码已提供 testnet-v1 的完整网络包及确定性重建工具，但尚无任意网络的通用创建向导。** 新身份还需配套 Rust/Go registry 支持、验证器和发布工具适配。只复制目录、修改 ID，不能让原安装包自动支持新网络。本章给出规划、配置关系和交付顺序；通用生成器不属于当前已有功能。

## 新网络意味着什么

每个独立网络都有自己的创世块、USDB 区块历史、账户余额、合约运行状态和节点成员。多个网络可以读取同一条 Bitcoin 链，也可以采用相同经济公式和 SourceDAO 合约代码，但仍需明确各自的规则作用域和网络身份。

| 你的目标 | 是否需要新网络 |
| --- | --- |
| 增加节点、部署 Explorer、换服务器或修改资源配额 | 不需要，使用原网络包和身份 |
| 为现有链启用新协议规则 | 规划该网络的高度激活和兼容升级；不重新生成已有链的 genesis |
| 清空可重置测试网，从 USDB block 0 重新开始 | 创建新的网络代际，重新生成身份与创世材料，再协调节点切换 |
| 运行另一个独立测试网或平行主网 | 独立身份、规则作用域、数据和发布物；不能仅改显示名称 |

不同网络的规则作用域使测试升级不自动影响其他网络，但不代表 Bitcoin 铭文专属于某条 USDB 链：当前 V2 mint JSON 没有 chain ID，同一 BTC 事实可能被多个网络按各自 origin 和规则识别。不要把它宣传成跨网资产隔离、独占矿工资格或自动跨链转移。

多个平行网络也不会因使用同一套代码而自动共享 USDB 余额、SourceDAO 治理或合并处理能力。跨网资产和任务分配需要另行设计。

## 先填一份网络参数清单

把下表的“需要决定”填完，就有了一份可以交给构建维护者评审的输入；不要直接复制 testnet-v1 的身份作为自己的网络身份。

| 类别 | 需要决定 | 为什么 |
| --- | --- | --- |
| 用途和生命周期 | 实验网／可重置测试网／长期网络，负责人和通知渠道 | 确定数据保留、升级和停止服务的安排 |
| 网络身份 | 名称、独立 chain ID、network ID、bundle ID、rules scope | 钱包、P2P、规则和数据目录各有对应身份 |
| Bitcoin 来源 | mainnet 或隔离测试来源，索引起点及对应块哈希 | USDB 从哪个 BTC 历史开始计算；真实 BTC 是否会被使用 |
| 协议规则 | MinerPass、能量、发行和费用规则的受支持版本，两个高度轴的激活安排 | 配置只能选择程序已实现的规则 |
| SourceDAO | 合约版本、自己控制的初始化管理员、初始分配和委员会名单 | 相同合约代码不代表相同治理归属 |
| 首个矿工 | 按目标规则取得的有效标准证、收益地址和运行负责人 | 首节点需要形成可验证的 BTC 状态并开始产块 |
| 接入方式 | Seed、P2P 端口、公共 RPC、浏览器和运营文档 | 后续节点需要可发现、可核验的入口 |
| 启动数据 | 从头同步或兼容的签名启动数据、信任公钥和分发位置 | 启动加速不能省略网络和数据身份校验 |

项目当前使用日期加当日序号选择测试网 ID；这只是编号约定，不提供全局唯一性保证。对外提供网络前，应核对目标使用范围内的冲突，为独立网络选择新 ID。genesis hash、registry ID 和文件 SHA-256 **由生成工具计算**，不是在清单里自行编造的数值。

## 从清单到可安装网络

1. **冻结输入**：确定上表参数及适用的程序版本，明确哪些 SourceDAO/BTC 输入可以复用、哪些必须重新生成。文件关系见[配置说明](configuration.md)。
2. **完成程序和工具支持**：由维护者加入该作用域的 registry、跨语言校验和网络包验证规则，并确认发布工具能选择该网络。遇到“不支持的网络／registry”应补齐实现，不删除校验绕过。
3. **生成并核验网络包**：从链 bootstrap 和 SourceDAO 配置生成 genesis、清单、摘要及发布材料。固定输入应能重建出相同结果；修改 chain ID 后不能保留旧系统账户状态。
4. **隔离验收**：使用全新数据目录，测试首节点初始化、有效矿工证、产块、SourceDAO 初始化、第二节点同步和重启。还要验证错误 genesis、registry 和旧网节点会被拒绝；本机目录或容器启动成功不是入网验收。
5. **交付并部署**：发布该网络的安装器、节点包及接入资料。普通参与者从安装器开始；首节点负责人按[首个矿工](../node/mining.md#网络首节点启用挖矿)、[SourceDAO 初始化](../network-admin/sourcedao.md)完成启动，持续确认出块后提供 Seed。

构建和签名材料的详细复现步骤以 [testnet-v1 发布说明](../../publish/usdb-testnet-v1-network-bundle.md)为现有实例。该实例中的生成命令只重建 testnet-v1；它不是填写任意 chain ID 的建网命令。向公众发布自己的网络时，还需提供自己的制品地址和版本选择支持，不能让安装器默认下载官方另一网络的包。

## 已有网络怎样升级或重置

同一条长期运行的链，协议升级应通过该网络的 registry 和 USDB activation checkpoints 安排；BTC 高度决定 Bitcoin 侧规则，USDB 高度绑定链侧策略和 registry。节点必须具备升级前后所需规则，配置一个未来版本字符串不会自动实现它。当前程序只执行 MinerPass V2，后续 V3/V4 的历史兼容需单独实现。

开发网重置则发布一套新的身份和数据目录，提前说明停止旧网的时间、哪些状态放弃、怎样重新加入。旧节点不会因公告或新包自动消失；它们仍可能维持旧链，但不得被当作新网 peer。不要让新旧实例并发写同一个数据库或使用同一宿主机监听端口。

Bitcoin 数据的兼容复用不等于复用 USDB 链数据。能否复用 Balance History、快照和 checkpoint，必须按各自的模式、origin、哈希及存储合同判断；不能通过改目录名让旧状态伪装成新网络。密钥和钱包备份也不属于可随旧链一起清除的数据。

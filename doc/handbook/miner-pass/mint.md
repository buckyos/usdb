# 使用铭文钱包铸造标准矿工证

[矿工证介绍](README.md) · [转让、换地址与协作](manage.md) · [CPU 挖矿](../node/mining.md)

本页面向 **MinerPass V2 新规则及配套控制台**，适用于明确启用 V2 的网络。当前源码改进不代表既有公开测试网已完成升级；铸造前先核对目标网络的发布说明和节点规则版本。

本页适用于**首次铸造标准矿工证**。已有旧证，需要换收益地址或保留能量时，先读[重新铸造并继承旧证](manage.md#重新铸造并继承旧证)，不要直接重复本页的空继承流程。

## 1. 准备钱包和地址

准备以下信息：

- 支持 Bitcoin **主网**自定义文本或 JSON 铭文铸造、接收和转移的钱包，以及支付铸造费用所需的 BTC。
- 来源地址 D：提供实际铭文 sat 的 commit 输入地址。付款钱包名或手续费支付地址不一定就是 D。
- 接收地址 E：你控制的全新 Bitcoin 地址。在 reveal 交易执行前余额必须为零，且在此 USDB 规则作用域内从未持有有效 pass；旧证转走、销毁或余额归零不会清除历史占用。
- 如采用冷地址策略，E 推荐使用从未暴露公钥的原生 P2WPKH 地址，不要为验证草案签名。Taproot 输出公钥本身公开；仅更换成新 Taproot 地址不满足隐藏公钥的目标。
- 你控制的 USDB 收益地址，格式为 `0x` 加 40 个十六进制字符。它是账户地址，不是私钥，也不是 Bitcoin 地址。

从钱包复制完整收益地址并核对，不使用他人的示例地址或自己无法控制的地址。收益到账后，支出 USDB 需要该账户对应的签名权限。网络及钱包接入资料从[测试网资料](../networks/testnet.md)取得。

各钱包界面名称不同，下面按操作目的说明。使用能够原样提交文本的铭文入口；BRC-20 的代币名称、数量表单不适用于本流程。

如果借助钱包内的代铸服务，确认它在铸造时直接把铭文交付到你的接收地址。若服务先铸到平台地址、之后再转给你，这属于矿工证转让，证会变为 `dormant`，还需要按[转让后的继承流程](manage.md#重新铸造并继承旧证)重新铸造。

建议先在控制台“MinerPass V2 铸造与核验”填写 D、E 和收益账户，生成完整 JSON。预检按已确认索引高度观察资格；小额转账、地址抢占、待确认交易或重组仍可能改变 reveal 时的结果。新地址已被干扰或占用时，换另一个全新地址重新准备，**核验通过前不要转入持币余额**。

最低安全承诺是防止用户没有主动操作时的既有权益侵害。持证地址应专用于明确的 pass 操作；普通或被诱导的付款、错误铸造仍可能改变 pass 权益。向恶意 commit 地址付款可能被解释为来源参与，来源检查不等于单独授权铭文内容。

## 2. 准备铭文内容

将下面内容保存为 UTF-8 纯文本文件 `usdb-pass.json`，或粘贴到钱包的自定义文本铭文输入框：

```json
{
  "p": "usdb",
  "op": "mint",
  "v": 2,
  "usdb_main": "YOUR_USDB_REWARD_ADDRESS"
}
```

**必须把 `YOUR_USDB_REWARD_ADDRESS` 替换为你自己的完整收益地址。** 占位符本身不是有效地址，不能直接拿模板铸造。

| 字段 | 怎样填写 |
| --- | --- |
| `p` | 固定为小写字符串 `"usdb"` |
| `op` | 固定为小写字符串 `"mint"` |
| `v` | 固定为整数 `2`，不要写成字符串 `"2"` |
| `usdb_main` | 自己的 USDB 收益地址；后续 `mining check --address` 使用同一地址 |

首次铸造不需要 `prev`。不要添加代币数量、名称、`usdb_collab`、网络 ID 或其他自定义字段；v2 会拒绝未知字段和重复字段。Bitcoin 接收地址在钱包里填写，不添加到这份标准证 JSON。

提交的是从 `{` 到 `}` 的 JSON 内容，不包括 Markdown 的反引号、说明文字或文件名。若钱包要求指定内容类型，使用 `application/json` 或 `text/plain;charset=utf-8`；不要上传截图、压缩包或把文件包装成其他 NFT 元数据。

## 3. 在钱包中铸造

1. 打开钱包的自定义文本或文件铭文入口，选择准备好的内容。首次操作选择**一次铸造一张**，不要批量重复提交。
2. 设置 E 为铭文接收地址，核对 Bitcoin 网络并确认 reveal 直接交付到 E；确保实际铭文 sat 来自预期 D。首次开户的资格豁免不代表系统替你确认了来源。
3. 查看待铸造的原始内容，确认 `usdb_main` 完整正确、`v` 是数字、模板占位符已替换。
4. 核对钱包列出的 Bitcoin 网络费、可能的服务费和随铭文交付的 BTC 金额，再确认签名并广播。
5. 保存钱包提供的交易记录和完整 **inscription ID**，等待铸造及交付完成。

钱包可能显示 commit（提交）和 reveal（揭示）两步交易。只有付款或 commit 成功，尚不能说明矿工证已经创建；需要等到携带铭文内容的 reveal 交易确认，并核对最终归属。

`pass_id` 使用完整 inscription ID，包括末尾的 `i` 和序号。不要使用订单号、单独的交易哈希或展示用的铭文总序号，也不要自行给交易哈希拼上 `i0`。一笔交易可以包含不同的铭文序号，以钱包返回的真实 ID 为准。

广播后无法原地修改铭文。地址填错但格式合法，仍可能被识别为有效证并将收益指向错误地址，所以必须在签名前核对。

## 确认矿工证生效

铸造完成后，先到控制台填写预期 D、E、完整收益／Leader 配置、`prev` 和钱包返回的指定 inscription ID，点击“核验后再入金”。如已知选用的来源 UTXO，也可填写 `txid:vout`。

工具核对该 ID 为 V2 Active、mint/current owner 均为 E、来源 D 及支持的签名形式、完整配置、prev 消费结果，以及规范链确认数。首次开户的存储审计可省略来源，工具会只读重建；缺历史区块或 undo 等证据时显示无法核验，不把协议有效或钱包到账当成可入金。该工具支持 P2PKH/P2WPKH SIGHASH_ALL 和 P2TR key-path DEFAULT/ALL 来源；其他形式的首开可能协议有效，但本工具不提供入金通过提示。

核验结果是指定高度的观测，不是持续保证；配置、账户、网络变化和查询失败会清除旧结果，成功提示短时过期后需要重验。**通过后再往 E 转入 BTC**。结果不符时先查原因，必要时换新地址重新铸造。

手工核对也应覆盖以下内容：

### Bitcoin 上的内容和归属

在钱包的铭文详情中核对原始 JSON、完整 inscription ID、reveal 交易是否确认，以及当前持有地址。钱包显示“铸造成功”只说明 Bitcoin 侧交易完成，还需要等待 USDB 索引与资格检查。

### USDB 的稳定高度已覆盖铸造高度

当前网络使用落后 Bitcoin 链尖端 **10 个区块**的稳定状态。如果 reveal 在 BTC 高度 `H` 确认，通常需要链尖端至少到 `H + 10`，并且相关索引服务已经处理到 `H`。例如铸造高度为 `967200`，先等待链尖端达到 `967210`，再检查 USDB 索引进度。

这不是固定等待十分钟；Bitcoin 出块、索引追赶和临时重组都会影响时间。如果服务还在同步，额外铸造不会加快生效。

有自己节点时运行：

```bash
usdb-node status --watch
```

观察 Bitcoin、Balance history 和 USDB indexer 的实际高度，详见[状态与同步进度](../node/status.md)。Ctrl+C 只退出观察。

### 查询资格

已完成部署和入网的普通节点，在原运维账号下执行：

```bash
read -r -p 'Miner reward address: ' USDB_MINER_ADDRESS
usdb-node mining check --address "$USDB_MINER_ADDRESS"
```

输入的地址必须与铭文 `usdb_main` 一致。看到 `state=READY` 后，核对 `Address`、`Pass`、`state=active/standard` 和 `BTC height`。如果该收益地址对应多个候选证，工具会自动选择一张；`READY` 不能单独证明刚铸造的那一张被选中，需要同时核对 `Pass`。

只有负责创建网络的初始化负责人使用 [CPU 挖矿章节的首节点分支](../node/mining.md#网络首节点启用挖矿)。普通加入节点不加 `--first-node` 来绕过连接检查。

没有自己节点时，使用网络运维方确认支持矿工证查询的服务，或请其按完整 `pass_id` 查询。核对**查询高度、当前持有地址、`active/standard` 状态和 `usdb_main`**；普通 Bitcoin 铭文展示页或仅显示 USDB 区块的浏览器不一定提供这些协议状态。[网络资料](../networks/testnet.md)尚未公布矿工证查询入口时，不要猜测接口地址。

确认有效后，按 [CPU 挖矿](../node/mining.md)启用矿工。仅执行 `mining check` 不会启动挖矿。

## 铸造后常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 已付款，但没有 inscription ID | 检查钱包订单、commit/reveal 进度和失败原因；确认原交易状态后再决定是否重试，避免重复下单 |
| 钱包看得到，USDB 暂时查不到 | 核对 Bitcoin 主网、内容类型、原始 JSON 和 ID；确认稳定高度及索引已覆盖 reveal 高度 |
| 地址一致，但没有合格证 | 核对证是否 `active/standard`，是否已转到其他地址或被新证替换；协作证不能用于独立挖矿 |
| 刚收到代铸铭文，却是 `dormant` | 检查是否先铸到服务方地址再转给你；这属于转让，需要在自己的持有地址[重新铸造并继承](manage.md#重新铸造并继承旧证) |
| `invalid`、`INVALID_SCHEMA` 或 `INVALID_USDB_MAIN` | 检查数字 `v: 2`、地址长度、占位符、未知或重复字段；原铭文不能编辑，查清后再准备新内容 |
| `AMBIGUOUS_REVEAL_INPUT` | 批量铸造让多张 USDB 铭文共用了同一个 reveal 输入；请钱包服务方确认原因，下一次改用独立单张铸造 |
| `INELIGIBLE_RECIPIENT` | E 在 reveal 前已有余额或有效持有历史；初次开户换全新地址，已有证按来源/继承流程操作 |
| `energy=0` | 首次铸造的正常起点；检查持有地址的实际 BTC 余额及后续稳定高度，零能量本身不阻止标准证挖矿 |
| `BITCOIN_NOT_READY`、RPC 错误或 `CHAIN_NOT_RUNNING` | 属于节点预检问题，按[矿工常见问题](../node/mining.md#常见问题)处理，不要因此重新铸造 |
| 收益地址填错或想更换 | 原证无法改字段，按[重新铸造并继承旧证](manage.md#重新铸造并继承旧证)处理 |

请求协助时提供网络、钱包名称及版本、完整 `pass_id`、reveal 交易哈希与高度、铭文内容和脱敏后的错误输出即可，不提供助记词、私钥或钱包备份。查询失败不一定会产生 `invalid` 记录；格式或内容类型完全不符合要求的铭文也可能直接不被识别。

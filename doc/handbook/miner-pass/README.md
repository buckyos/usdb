# 认识矿工证

[返回手册首页](../README.md) · [首次铸造](mint.md) · [转让、换地址与协作](manage.md)

**矿工证（Miner Pass）是一份记录在 Bitcoin 上的铭文，用来声明 USDB 挖矿身份。** 想自己运行矿工，先铸造一张标准矿工证，等待它被 USDB 网络识别为有效，再按 [CPU 挖矿](../node/mining.md)启用节点。只安装或运行普通节点，不需要矿工证。

本章面向当前 `usdb-testnet-v0` 使用的矿工证 v1，规则核对日期为 **2026-09-19**。USDB 网络身份与接入信息见[测试网资料](../networks/testnet.md)。这里的 Bitcoin 数据源是**主网**，铸造需要实际的主网 BTC；USDB 测试币不能支付 Bitcoin 交易费用。

铸造矿工证可以在准备节点期间进行，不要求先自建 USDB 节点。实际启用本机挖矿时，节点同步、入网和矿工资格都需要通过检查。

## 分清两个地址和一个编号

| 名称 | 用途 | 从哪里取得 |
| --- | --- | --- |
| Bitcoin 持有地址 | 接收并持有矿工证；该地址的 BTC 余额参与能量计算 | 铭文钱包中你控制的 Bitcoin 主网接收地址 |
| USDB 收益地址，即 `usdb_main` | 标准矿工证声明的挖矿地址，用于接收 USDB 挖矿收益 | 你控制的 EVM 账户地址，格式为 `0x` 加 40 个十六进制字符 |
| 矿工证编号，即 `pass_id` | 唯一标识某一张矿工证，用于查询、继承或绑定协作对象 | 铸造完成后的 inscription ID，格式为 64 位小写交易哈希加 `i` 和序号 |

`usdb_main` 填在铭文内容里；Bitcoin 接收地址填在钱包的接收位置，两者不能互换。支付铸造费用的地址也不一定是最后持有矿工证的地址，以铭文实际归属为准。

同一个钱包可能管理多个 Bitcoin 地址。USDB 按**持有矿工证的具体地址对应的余额**计算能量，不使用整个钱包显示的合计余额；同一钱包内换到另一个地址，通常也属于转让。

矿工节点只需要 USDB 收益地址，不需要导入 Bitcoin 钱包或收益地址的私钥。钱包负责保管资产和签署钱包交易。

## 标准证与协作证

| 类型 | 适合谁 | 铭文填写什么 | 能否作为独立挖矿身份 |
| --- | --- | --- | --- |
| 标准矿工证 `standard` | 自己运行矿工的人，也可作为协作的 Leader | `usdb_main` | 处于 `active` 且通过矿工预检时可以 |
| 协作矿工证 `collab` | 希望把自身能量贡献给 Leader 的人 | `leader_pass_id` 或 `leader_btc_addr` 二选一 | 不可以；协作身份与收益接收使用 Leader 的 `usdb_main` |

第一次准备自己挖矿，选择**标准证**。协作证不会自动给持有人另发一份奖励，收益分配需要另行约定，详见[协作说明](manage.md#协作矿工证)。

## 持有矿工证后会发生什么

一张新铸造且没有继承旧证的矿工证，初始能量为 `0`。有效标准证即使能量为零，也可以通过资格检查，按完整基础难度挖矿。铸造成功不会自动启动矿工，也不保证产块或收益。

能量用于计算挖矿等级和难度，不是钱包里的 USDB 余额，不能当作固定收益领取。当前 v1 的基础规则是：

- 证处于 `active` 时，按持有地址的 BTC 余额和经过的 BTC 区块积累自身能量；铸造前的持币时间不补算。
- 每满 `100000 sats`，即 `0.001 BTC`，算一个余额单位；每单位每个 BTC 区块增长 1 点自身能量。例如余额持续为 `0.0024 BTC`，按 2 个单位增长。
- 少于一个单位时没有新的余额能量增长，但这不是挖矿最低余额门槛。
- BTC 仍由持有人控制，不需要为能量转入项目方账户。余额减少、找零转到其他地址或支付手续费导致余额单位减少时，已有能量可能被扣减，后续增长也会改变。

协作带来的有效能量与证自身能量有区别；继承只继承旧证自身的能量。预检里的 `energy`、`level`、`difficulty` 和发行估算见[读懂预检输出](../node/mining.md#读懂预检输出)。

## 看懂矿工证状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `active` | 该持有地址当前生效的证；是否能独立挖矿还要看类型 | 标准证继续矿工预检；协作证检查 Leader 绑定 |
| `dormant` | 已冻结，不再增长能量或参与挖矿；常见于转让或被新证替换 | 需要使用时按[继承流程](manage.md#重新铸造并继承旧证)铸造新证 |
| `consumed` | 已被新证继承消费 | 使用新证，旧证不能再次继承 |
| `burned` | 已销毁，失去经济作用 | 无法恢复原证 |
| `invalid` | 铸造内容或继承等前置条件不符合规则 | 查明原因，原铭文不能直接修改成有效证 |

**同一 Bitcoin 持有地址最多只有一张 `active` 证，标准证和协作证共用这个名额。** 在同一地址再次铸造有效证，会让原活跃证退出活跃状态；仅仅多付一次费用、多铸一张，并不会叠加挖矿身份。等待索引期间不要用重复铸造来“刷新”。

## 当前与后续操作入口

目前使用支持**自定义文本或 JSON 铭文铸造**的钱包完成交易，操作见[首次铸造](mint.md)。仅能查看或转移铭文的钱包，不一定能铸造本协议需要的内容。

后续计划提供 **control-plane + 浏览器钱包** 的流程，由页面生成铭文、展示费用并发起钱包签名。本手册暂不将该流程作为已发布能力；上线后会补充入口、兼容钱包及操作步骤。现阶段不需要部署 control-plane 才能铸造。
